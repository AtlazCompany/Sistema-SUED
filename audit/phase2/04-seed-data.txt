SUED SYSTEM — FASE 2 — 04. DADOS INICIAIS (SEED)
=============================================================

O banco está praticamente vazio (User=1, todas as outras 22 tabelas=0).
Isso NÃO é um bug — é o estado esperado de um banco recém-criado, sem
nenhuma empresa real ainda tendo usado o sistema.

TABELAS INVESTIGADAS
-----------------------
EventType ........ CATÁLOGO DE APOIO. 0 registros hoje. NÃO existe
                    nenhuma tela/rota de CRUD para EventType em todo o
                    código (confirmado por leitura de todas as rotas —
                    só há SELECT id,name em server/routes/eventos.js,

ProductService .... CATÁLOGO DE APOIO (produtos/serviços) com tela de

Supplier .......... CADASTRO com tela de CRUD completa. Pode começar

CLASSIFICAÇÃO
---------------
Nenhuma dessas tabelas exige seed técnico obrigatório para o sistema
FUNCIONAR (o backend não quebra com elas vazias — todos os campos que
apontam para elas são opcionais/nullable no schema, confirmado em
08-database.txt). O que falta é DADO DE NEGÓCIO, que só a empresa sabe
(quais tipos de evento oferece, quais fornecedores usa, quais produtos
vende) — por isso NÃO foram inventados dados de exemplo permanentes.

O único dado tecnicamente indispensável para o sistema ser utilizável é
o usuário administrador — que já existe (1 usuário ADMIN ativo,
confirmado em 02-user-management.txt).

RECOMENDAÇÃO PARA PRODUÇÃO (não executada nesta fase — decisão de
negócio da empresa, não uma correção técnica)
------------------------------------------------------------------------
Antes do primeiro uso real, a empresa (via ADMIN) deveria cadastrar
manualmente pela própria UI: pelo menos 1-2 EventType relevantes ao
negócio, os Venue próprios (Palácio SUED, Espaço SUED, etc., conforme
mencionado no README do projeto), e o catálogo inicial de
produtos/serviços/fornecedores mais usados. Isso é operação normal do
sistema, não uma pendência técnica.
