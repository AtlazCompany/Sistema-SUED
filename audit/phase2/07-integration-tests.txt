SUED SYSTEM — FASE 2 — 07. TESTES DE INTEGRIDADE ENTRE MÓDULOS
=============================================================
Testados fluxos completos de ponta a ponta, não módulos isolados —
usando os MESMOS IDs reais entre as chamadas, exatamente como um
usuário faria na prática.

FLUXO COMERCIAL: Lead -> Cliente -> Oportunidade -> Orçamento ->
                 Contrato -> Evento
------------------------------------------------------------------------
1. Lead criado (POST /leads) .......................... VALIDADO
2. Lead convertido em Cliente (POST /leads/:id/converter) VALIDADO —
   Client criado com os dados copiados do Lead; Lead atualizado com
   status=CONVERTIDO e clientId apontando para o Client novo.
   CONSISTÊNCIA CONFIRMADA: relendo a lista de Leads depois da
   conversão, o registro aparece com status CONVERTIDO e o clientId
   correto.
3. Oportunidade criada vinculada ao Cliente convertido (POST
   /oportunidades com clientId=<id do cliente do lead>) ... VALIDADO
4. Orçamento criado vinculado ao mesmo Cliente + à Oportunidade + a um
   Evento (ver abaixo) ................................... VALIDADO
5. Contrato criado vinculado ao mesmo Cliente + Evento .... VALIDADO
6. Evento criado vinculado à mesma Oportunidade + Cliente + Local
   ......................................................... VALIDADO
   - REGRA DE INTEGRIDADE TESTADA: tentar criar um SEGUNDO evento
     apontando para a MESMA oportunidade -> REJEITADO com 400
     ("Essa oportunidade já está vinculada a outro evento"), a
     constraint UNIQUE("opportunityId") do banco foi respeitada de
     ponta a ponta (aplicação -> banco -> resposta amigável).

Todos os IDs permaneceram consistentes entre as 6 etapas — nenhum
relacionamento ficou órfão ou apontando para o registro errado.

2. Checklist criado vinculado ao Evento .................... VALIDADO
3. ChecklistItem criado vinculado ao Checklist .............. VALIDADO
   - Marcado como concluído -> doneAt preenchido automaticamente
     ........................................................ VALIDADO
4. ScheduleItem criado vinculado ao Evento .................. VALIDADO
5. CONSISTÊNCIA CONFIRMADA no painel consolidado (GET

FLUXO DE CATÁLOGO: ProductService -> SupplierProduct -> Supplier ->
                    BudgetItem

2. ProductService criado vinculado à Category ................. VALIDADO
3. SupplierProduct criado vinculando ProductService + Supplier

   - Refletido corretamente nos DOIS lados: detalhe do produto lista o

NOTA HONESTA SOBRE O PROCESSO: a primeira execução deste harness tinha
uma lógica de limpeza incompleta (não previa que BudgetItem e
Interaction são criados pelo backend sem devolver o id individual ao
chamador) e travou no meio da limpeza, deixando resíduo temporário no
banco. Isso foi detectado imediatamente (o processo terminou com erro,
não silenciosamente), corrigido com uma limpeza manual de emergência
(confirmada, banco voltou a User=1/resto=0), o script foi corrigido
para apagar por relacionamento/marca em vez de por lista de ids, e a
bateria completa foi executada novamente do zero com sucesso total e
sem travar. Registrando isso porque a regra desta fase é não esconder
falhas — inclusive as minhas, durante a própria auditoria.
